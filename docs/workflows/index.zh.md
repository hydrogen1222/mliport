# 工作流

mliport 能算的东西，归根结底就是下面这几种工作流。它们共用同一套模型选择、同一
套配置层次，并且都有一个习惯：在结果旁边写一份 `resolved_config.json`。

| 工作流 | 命令 | 用来做什么 |
|---|---|---|
| [单点](single-point.md) | `mliport sp` | 一个结构的能量、力和应力 |
| [弛豫](optimization.md) | `mliport opt` | 把力降到最小，可选地连同晶胞一起 |
| [分子动力学](md.md) | `mliport md` | 为分析准备的 NVE 或 NVT 轨迹 |
| [NEB / CI-NEB](neb.md) | `mliport neb` | 反应路径及其势垒 |
| [批量](batch.md) | `mliport batch` | 对许多结构做同一种计算 |
| [队列](queue.md) | `mliport queue` | 多个作业，一次只占一块 GPU |

`mliport run` 执行一个 INCAR 风格的文件，可以启动上面任何一种工作流；
`mliport template` 会写出一份带注释的模板，供你在此基础上修改。`mliport tui` 在交
互式终端应用里提供同样的工作流。

## 退出码

命令行、TUI 和队列对"一次运行是怎么结束的"口径一致，所以脚本可以分清"跑完了"
和"跑了但没收敛"：

| 退出码 | 含义 |
|---|---|
| `0` | 正常完成 |
| `1` | 失败（出错、配置有误、运行时故障） |
| `2` | 跑完了但没有收敛；部分结果和原因会保留 |
| `130` | 被取消（中断或协作式取消） |

没有收敛标记的弛豫或 NEB 结果，一律按"未收敛"处理。mliport 不会因为进程恰好正常
退出，就把一次运行说成成功。

## 跟踪运行进度

每次运行都会在输出目录里写一份实时的 `run.log`，并打印跟踪它的命令（`tail -f`）。
长时间的运行（包括 NEB）会一边跑一边往里报告进度，所以终端安静并不等于作业卡住。
