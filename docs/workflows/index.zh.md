# 工作流

mliport 将每次计算组织为一个**工作流**——一个自包含的单元，接受结构和模型，运行物理计算，并写入完整的运行记录。所有工作流共享相同的模型选择逻辑、相同的[配置层级](../configuration.md)，并且都会在结果旁写入 `resolved_config.json`，以便你随时重建确切的运行条件。

## 选择工作流

| 需求 | 使用 | 命令 |
|---|---|---|
| 检验模型能否加载并产生合理的力 | [单点计算](single-point.md) | `mliport sp` |
| 寻找势能面上最近的局域极小值 | [结构优化](optimization.md) | `mliport opt` |
| 采样热力学系综或生成用于输运分析的轨迹 | [分子动力学](md.md) | `mliport md` |
| 估算两个状态之间的反应或迁移能垒 | [NEB / CI-NEB](neb.md) | `mliport neb` |
| 筛选表面板上的低能吸附构型 | [构型搜索](confsearch.md) | `mliport confsearch` |
| 用同一模型对大量结构进行批量计算 | [批量计算](batch.md) | `mliport batch` |
| 将多个任务排入队列，分配 GPU 后无需值守 | [作业队列](queue.md) | `mliport queue` |

典型项目的流程为：**单点计算** → 确认模型加载正常、力的量级合理 → **结构优化** → 获得平衡结构 → **MD** → 生成轨迹用于性质提取 → **分析**。NEB 和构型搜索是分别面向能垒计算和表面吸附筛选的专用工作流。

## 四种启动方式

每个工作流都可以从以下入口启动：

1. **命令行** — `mliport sp`、`mliport opt`、`mliport md` 等。
2. **INCAR 风格文件** — `mliport run INCAR` 读取关键字文件（`CALC_TYPE = sp`、`MODEL_TYPE = mace` 等）并分发到相应的工作流。`mliport template` 可生成带注释的模板供你修改。
3. **Python API** — `from mliport.api import run_single_point` 及其他函数，可将计算嵌入脚本和 Notebook 中。
4. **终端 UI** — `mliport tui` 打开一个交互式应用程序，通过引导菜单暴露相同的工作流。

## 退出码

CLI、TUI 和队列都遵循相同的退出码约定，因此外层脚本可以在不解析日志文件的情况下区分"已完成"和"完成但未收敛"：

| 退出码 | 含义 |
|---|---|
| `0` | 成功完成 |
| `1` | 失败——配置错误、运行时错误或缺少输入 |
| `2` | 运行结束但未收敛；部分结果和原因被保留 |
| `130` | 被中断信号或协作取消终止 |

未带收敛标志的优化或 NEB 结果被视为**未收敛**。mliport 不会仅因为进程正常退出就认定运行成功。

## 跟踪运行进度

每次运行都会在其输出目录中写入实时的 `run.log`，并打印一条 `tail -f` 命令供你复制。长时间的运行——尤其是 NEB 和 MD——会在日志中持续报告进度，因此终端没有输出并不意味着任务卡住了。

## 模型身份与可重复性

每个工作流都在 `run_context.json` 中记录**模型身份**：后端、模型路径、文件哈希、task、head、dtype、推理模式、设备以及任何 DFT-D3 校正。只有模型身份完全匹配的两个结果才具有可比性。来自不同模型、或同一模型使用不同 head 或 task 的绝对能量不可混用。
